# Contributing

Thank you for helping improve this UI/UX design skill. The repository is documentation and templates for AI-assisted product design; contributions should make the guidance more useful, evidence-aware, accessible, and practical across platforms.

## Before proposing a change

For a significant new capability, workflow, or source set, open a GitHub issue first. Describe the user or practitioner problem, the relevant product context, the evidence behind the proposal, and which existing skill files may need updating. Small corrections and focused clarifications can go directly into a pull request.

## Contribution principles

- Keep core instructions portable across assistants and frontend frameworks. Put platform-specific behavior in the appropriate reference and label its scope.
- Separate standards, empirical evidence, expert recommendations, commercial advice, and assumptions. Do not present a heuristic as a universal requirement or a causal outcome.
- Prefer authoritative primary sources for standards and platform details. Cite sources near the claims they support and note material limitations, dates, or access issues.
- Do not copy substantial passages, examples, screenshots, illustrations, fonts, or other third-party material without permission. Summarize briefly in your own words and link to the source.
- Do not add invented user research, metrics, testimonials, product facts, or claims that work was tested when it was not.
- Keep edits focused, use clear headings, preserve relative links, and update the knowledge-library routing when adding a reference file.

## Pull-request checklist

Before opening a pull request:

1. Explain the problem and the intended improvement.
2. List changed files and any sources added or removed.
3. Check that internal Markdown links resolve and that citations point to the correct sources.
4. Note important assumptions, platform scope, and evidence limitations.
5. Remove accidental personal data, credentials, private screenshots, or unpublished user research.

## Copyright and permissions

This repository currently has no open-source license. Public visibility does not grant reuse rights. Because contribution terms have not been established, open an issue with the maintainer before submitting substantial original material so attribution and permission to include and maintain it in this public repository can be agreed. For third-party content, obtain the necessary permission and identify applicable license terms before proposing inclusion.
